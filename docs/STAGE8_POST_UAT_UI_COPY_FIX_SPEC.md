## 1. 範圍與優先原則

本輪僅處理四處使用介面：首頁、機台監控、機台運轉分析、Excel 匯入 Preview／成功回饋。**不修改異常事件分析頁 V2、不修改正式 SQLite schema、Collector 排程／企業 API Client、不任意改寫歷史計算公式或匯入交易語意。**

### 文案精簡與版面穩定（本輪必要驗收條件）

- 文案採「短標題／短數值標籤 ＋ 必要的一句白話說明 ＋ 可展開技術細節」三層。不可把原本短欄位一律替換成完整句子，導致小卡膨脹。
- 小型摘要卡：標題盡量 **4–10 個中文字**、數值單獨一行、補充描述盡量 **20 字內**；以上是排版預算而非硬切資料的限制。涉及來源狀態（如有來源但零筆）必須完整保留語意。
- 盡量維持桌面摘要卡的既有行高與格線；避免無必要的二行標籤、文字超出卡片、按鈕推擠、Tooltip 出界。不得透過縮小主文字到難讀的尺寸來「解決」溢出。
- 長說明放在群組下方、`details` 展開區或帶文字的資訊提示；重要錯誤不能僅在 hover 才可見，鍵盤與觸控也要能閱讀。
- 在 **1280／1366／1440px** 桌面寬度及 **760px** 窄螢幕檢查：水平溢出、卡片高度、長字串、換行、Tooltip、按鈕與表格列；避免固定高度把內容裁掉。只在被忽略的本機資料夾保存少量必要截圖，不加入 Git。
- 不只是「文案有換」，還要檢查在 8 份檔案、44 項品質提醒、0 警示、未提供 Alarm 與長檔名等情況下的版面。

## 3. 機台監控（參考 `02_machine_monitor.png`）

### 3.1 白話化，不混淆收集與畫面刷新

- 將「本機資料來源／SQLite 本機服務」等技術說明改為「資料狀態／平台資料庫」等使用者語彙；但不得暗示直接對企業感測器每 30 秒抓取。
- 「每 30 秒讀取本機後端」→「每 30 秒更新畫面」。企業資料收集仍是服務時段每 3 分鐘，由 Collector 負責。
- 確實區分「設備來源更新時間」、「平台接收時間」、「畫面刷新時間」；保留必要診斷細節於 API 設定頁，不要混稱為即時更新。

### 3.2 確認燈號種類、Demo 與資料安全

- 使用者確認的**設備顯示狀態**為：綠（加工中）、黃（待機／完成）、紅（異常狀態）、灰（未開機）；監控 UI 不顯示藍／白等未確認燈號，移除藍色「其他燈號」KPI。
- **灰／未開機必須有可核實的來源判定**；既有企業 API 契約並未保證可從五色值全 0 可靠推導 OFF。不得把全 0、stale 或無資料直接當未開機。若現行真實資料無可靠 OFF 來源，Live 保留「資料不可用／狀態未知」並在交付回報說明；不要杜撰辨識規則。
- 原始 API 欄位與歷史 Excel 六態是資料契約，不因監控 UI 精簡而刪除 Blue／White／None 原始欄位或 SQLite 資料。
- Demo 合成機台狀態以**綠、黃為主**，少量紅／灰（灰僅限確有明確 Demo 狀態設定）與資料不可用可用於驗收；不出現藍／白展示狀態。修改 Demo fixture 時保證 KPI、卡片、詳細資訊一致。
- Demo 所有 A1–B4「加工完成訊號」一律 OFF；**Live 仍顯示實際 ON／OFF 回報**，不得寫死或更改 Collector。
- A 區／B 區標題下「2 個測點達到／超過警示值」移除；本輪不必增加重複的區域設備統計文字。
- 統計卡若顯示分類數量，必須與 8 台設備卡一致；已確認灰／未開機與未知／資料不可用不得算在同一狀態內。

## 4. 機台運轉分析（參考 `03` 至 `07`）

### 4.1 提示圖示

- 「已切換為每日粒度」前的文字驚嘆號改為一致的**圓框驚嘆號 SVG icon**（建議沿用專案現有 Icon／Lucide）；`11_info_icon_reference.jpg` 只供外觀參考，不直接嵌入 JPG 或提交新素材。這是資訊提示，不是資料故障。

### 4.2 累積工時排行的 Tooltip

- 「有效區間」→「可統計資料」，例如 `3,360 / 3,360 筆（三分鐘紀錄）`；要核對 API 是否能提供正確分母，不能憑空補值。合格區間與實際加工秒數不是同一件事。
- 0 小時加工與缺少資料要有不同語意；若無可靠分母，優先用「可統計紀錄：3,360 筆」，不要造出完整度 100%。

### 4.3 圖表工時軸容量

- 對**固定 N 個完整日、單台設備**的累積工時：物理上限 `24 × N 小時`，排名圖應以此做座標最右端，不以漂亮整數推到 25／50 小時；例如 1 日 24 小時、2 日 48 小時、7 日 168 小時。刻度可選友善間隔，但最右端須為真實上限。
- 若圖表統計為多台加總，容量應再乘機台數；30／60 分鐘桶依桶長及合計機台數確認上限。必須先檢查目前圖表的聚合語意，**不要所有圖一律套上 24 小時**。
- 若資料因異常超過理論上限，不裁掉、不默默歸零；保留原值並出現可理解的資料異常說明，依既有驗證規則決定是否可統計。
- 改比例尺不改變 Green 原始統計、資料品質資格或公式。

### 4.4 趨勢標題與資料完整性詞彙

- 「A3、A1、A4、A2」若確為整個查詢區間的累計 Green 排行，顯示「累積加工時間排行：A3 ＞ A1 ＞ A4 ＞ A2」；若 API 沒有確定順位，必須從可驗證統計結果得出，不可只更換分隔符號。
- 「每日粒度」→「每日統計」；「部分覆蓋」→「部分資料缺漏」；「完整」→「資料完整」；「描邊點＝部分覆蓋」→「空心圓表示部分資料缺漏」。
- Tooltip 如有分子、分母，顯示「可統計資料：400 / 480 筆」；沒有資料時不要視為 0，也不可把來源未提供與有資料且全 0 混為一談。

### 4.5 比較百分比與占比摘要

- 相對變化：`(後期秒數 - 前期秒數) / 前期秒數 × 100%`。計算必須依**未四捨五入的秒數**，而非顯示成整數的小時。前期真正為 0 時，顯示「無法計算（前期為 0）」；前期非零但顯示值四捨五入為 0 時，仍應正確計算百分比並改善時間格式。
- 「整體占比」可保留合併後的占比變化摘要；「各機台占比」**移除最下方重複／可能誤認為逐機台值的整體占比摘要列**，個別差異改放各機台 Tooltip（有可靠值時）。
- 不變更三態占比分母、品質資格、同期比較的 A/B 獨立計算原則。
