# Stage 5.2 — Excel 匯入頁 UI 最終補修規格

> 文件性質：Stage 5.2 已完成之 Excel 匯入頁 UI／使用者體驗補修，不是新資料契約、統計規則或資料庫重建案。
>
> 優先級：正式修正授權規格。以本文件作為 UI 最終驗收標準；沿用 `STAGE5_2_EXCEL_DATA_QUALITY_EXECUTION_SPEC.md` 與 `STAGE5_2_EXCEL_IMPORT_UI_ADDENDUM.md` 中既有的資料安全、NULL、品質及匯入交易要求。若技術實作有衝突，優先維持資料正確性與非破壞性。

## 0. 背景、目前已確認成果與界線

Stage 5.2 目前已完成 nullable 欄位、`jiyin-quality-v2`、SQLite migration v2、逐檔 Preview／Confirm、品質摘要與版本追蹤，公開合成資料測試及瀏覽器驗收已由 Codex 回報通過。實際私人 2025/06/01–06/05 五份清洗後工作簿經使用者手動 Preview：6/1、6/2 顯示完全重複；6/3、6/4、6/5 顯示可新增；使用者確認後成功匯入 3 份，版本紀錄顯示累計 5 個來源日期。此次**不再重做或放寬資料規則**，以修正真實畫面中仍出現的 UI 缺陷為目標。

本文件對應使用者實際截圖中反覆出現的缺陷：

- 無 Preview 時，「匯入版本紀錄」與上方區塊無間隔。
- 有 Preview 時，「Preview 結果」與上方區塊無間隔；有時版本區塊有間隔，顯示布局受條件分支影響。
- 完成 Confirm、Preview 消失／重置後，「匯入版本紀錄」再次黏住上方區塊。
- 左側檔案清單增加時，右側固定規則卡留下大片空白，兩張卡高度不協調。
- Preview 雖已彙總部分警告，仍以兩欄多張大型卡片呈現，不符原本批准的「批次摘要＋精簡逐檔列表＋展開詳情」。
- 匯入版本紀錄欠缺直接點擊欄位標題排序、適合未來數百份資料的分頁控制；對一般使用者而言，批次 #1、#2… 沒有明顯意義。

## 1. 本次實作優先序

1. P0：不破壞既有匯入、Preview 唯讀、交易／版本回復、`jiyin-quality-v2` 與統計資格。先建立必要的回歸測試。
2. P1：重整上方選檔區為單一全寬操作卡片，從根本消除左右高度與空白問題。
3. P1：修正所有條件狀態下主要區塊間距，實際量測每對可見區塊 **24 CSS px**。
4. P1：Preview 實作真正的批次摘要、單列式精簡逐檔結果、可展開詳情。
5. P2：版本紀錄欄位與排序、日期搜尋、每頁筆數與分頁，以及同日版本與批次 ID 語意。
6. P2：完成 1280／1366／1440px 真實瀏覽器操作與布局量測，更新驗收文件。

## 2. 匯入區塊：改為單一全寬操作卡片（已確認採用）

**設計決策：不用保留原有「左選檔、右匯入規則」的兩張並排大卡片。** 改為單一全寬的「Excel 資料匯入」操作區；維持既有深酒紅品牌設計、字體風格及可操作的上傳區。

基本結構（由上而下）：

1. 卡片標題＋限制摘要（最多 8 份、單檔 25 MiB、整批 50 MiB；以真實後端限制為準）。
2. 原本的「匯入規則」改為一個容易找到、可鍵盤操作的「查看匯入規則」展開／收合區，預設收合；展開後顯示三條已核准規則，不刪除重要說明。
3. 檔案選取／拖曳區（如原本有拖曳功能則保留；若沒有，不要僅因文案而宣稱支援拖曳）。
4. 已選檔案數、總大小、清除全部；每份檔案為精簡清單項目，可單獨移除。
5. 檔案清單**設最大高度約 320–400 CSS px**，超出使用清單內部捲動；不讓每增加一檔就無限制拉長外層卡片。
6. 「預覽並驗證」操作，包含 Loading／停用與避免重複送出。

外層操作區自然高度；不要留下固定空白去對齊不存在的右側卡片。對未選檔／1 檔／5 檔／8 檔狀態，卡片內容不截斷、操作按鈕可達。

## 3. 各主要區塊間距：必須真正修好，不再以 CSS 宣告代替驗收

主要區塊為：`SelectionSection`（全寬匯入操作卡）、`PreviewSection`（有 Preview 結果才顯示）、`HistorySection`（匯入版本紀錄）。

**驗收目標：依畫面上實際出現的相鄰主要卡片，其外框之間垂直距離 = 24 CSS px（允許 ±2px 量測誤差）**，不受 Preview 顯示或消失、檔案筆數、Confirm 成功、資料重整影響。

須驗證的狀態：

- S1：未選檔、沒有 Preview → Selection 與 History 間距 24px。
- S2：選 5 或 8 份，但尚未 Preview → Selection 與 History 間距 24px。
- S3：Preview 已完成 → Selection／Preview 間距 24px；Preview／History 間距 24px。
- S4：Confirm 成功後（Preview 保留、隱藏或重設皆可，需符合現有 UX）→ 所有**仍可見**相鄰主區塊間距 24px。
- S5：驗證失敗／錯誤狀態及 Loading → 不重疊，主要卡片間距不失效。

建議從頁面層級維護一致的 stack／grid `gap`，不要靠每個卡片不同的條件式 `margin` 拼接。**在瀏覽器使用 `getBoundingClientRect()` 量測實際 DOM 邊界**，提交數值與截圖；只確認 `.css` 中存在 `gap:24px` 不算通過。

## 4. Preview：批次摘要＋精簡逐檔清單＋展開詳情

不能僅把兩欄大型卡片縮小或收起警告文字；必須真正改變資訊架構。

### 4.1 批次摘要

在 Preview 區塊頂部固定呈現本次查詢的實際計數：檔案總數、可新增、完全重複、需要確認替換／衝突、驗證失敗，以及品質警告摘要（可採適合尺寸的簡潔卡片或計數列）。各決策可能同時伴隨警告，須避免重複加總或誤導。

### 4.2 逐檔摘要列表

- 一檔**一列**，優先顯示：來源日期、精簡檔名（過長可截斷且提供完整檔名）、決策狀態、問題數量、展開／收合控制。
- 5～8 檔應呈現為單欄列表或表格，而不是兩欄等高大型卡片。
- 使用色彩與文字雙重表達 `INSERT`／`DUPLICATE`／`CONFLICT`／`INVALID`／含品質警告，不只靠顏色。
- 清單過長時最大高度約 **440–480 CSS px**，清單內部可捲動；標題、批次摘要與 Confirm 操作不要跟著整個列表捲走到難以找到的位置。
- 若展開詳情後內容長，詳細警告區也要妥善限制高度／保留捲動，避免一份檔案列出上百行警告撐爆頁面。

### 4.3 展開詳情

展開後才呈現該檔的機台／環境／Alarm／品質筆數、資料到達率與分指標有效率、錯誤／警告分組與中文說明、來源列號例子及技術代碼。不得刪掉任何有用的驗證細節，也不能僅用「可匯入」掩蓋 `SEVERE` 品質異常。

### 4.4 Confirm

保留現有 Preview 唯讀、Confirm 才寫入、逐檔交易、完全重複跳過、同日版本替換明確確認、`ACTIVE_VERSION_CHANGED` 重查提示、錯誤隔離及載入防重複送出。若批次同時有重複／新增／無效檔，必須明確讓使用者知道哪些會寫入、哪些不會，不能無聲忽略。

## 5. 匯入版本紀錄：排序、分頁、欄位語意

### 5.1 排序與查詢

- 預設：來源日期**新到舊**；日期相同時以匯入時間／可靠次序排序。
- 點擊支援排序的表格欄位標題，可切換升冪／降冪；需顯示目前排序欄位與方向，並支援鍵盤操作及 `aria-sort`（如適用）。
- 至少支援「來源日期」、「匯入時間」排序；如有真正可靠的同日版本序號，才提供「版本」排序。不得把全域 Batch ID 誤當同日版本號。
- 保留日期／檔名搜尋（若原欄位已支援）；篩選及排序應先套用在**完整查詢結果**再分頁，不可只排序當前 10 筆。
- 大量資料時採後端排序／分頁或能保證一致性且合理擴展的方式，避免只用前端載入全部歷史版本。不得破壞既有版本 Activate／Rollback 行為。

### 5.2 表格高度與分頁

- 每頁預設 **10 筆**，可選 20／50 筆。超過每頁上限以分頁切換；顯示總筆數與目前頁次。
- 「高度固定」在此定義為**每頁列數受控、表格不因歷史筆數無限增高**。只有 5 筆時不應硬塞出 10 筆高度的大量空白；不需要在表格內再疊加另一個垂直捲軸。
- 切換篩選或每頁筆數時，安全地重設／修正目前頁碼，避免跳至空頁。

### 5.3 批次 ID 與真正的版本號

- **SQLite Batch ID／Import Batch 必須保留**，用於交易、來源追溯、Active 版本及回復；本次不刪資料庫欄位、不任意更改資料表或金鑰。
- 主表移除不直觀的全域「批次 #1／#2」欄位，改顯示更有用的「同日版本（若可可靠取得）」、「匯入時間」及啟用狀態。
- 不得把「第 5 個匯入批次」解讀成「同一天的第 5 版」。若無法從既有資料安全算出同日版本序號，可先只顯示匯入時間與啟用狀態，詳細資料再顯示 Batch ID；不要為 UI 擅自進行高風險 Migration。
- 在詳情視窗／展開列保留 Batch ID、來源檔名、指紋／時間、同日版本／啟用狀態、品質資訊以及現有版本回復操作。
- 保持「每個來源日期最多一個 Active Batch」與原有版本替換／回復安全規則。

## 6. 最低限度的實測案例與驗收證據

使用公開合成 Excel 與拋棄式 SQLite／測試服務完成瀏覽器測試；私人企業資料不得提交至 Git。若本機使用者有實際五日工作簿，可唯讀、隔離地額外測試，不應覆寫目前已有 Active Batch。

| 編號 | 操作與輸入 | 必須驗證 |
|---|---|---|
| U-01 | 未選檔、未 Preview，版本紀錄已有資料 | 只有選檔區與版本區；兩者 24px；無右側大空白 |
| U-02 | 選 1 份，再選 5 份／8 份 | 選檔清單最多約 320–400px、可移除單檔／清除、規則可展開 |
| U-03 | 五份測試日（模擬兩重複、三新增，含品質警告）按 Preview | 批次摘要、逐檔一列、狀態正確、展開詳情正確；Selection／Preview／History 各 24px |
| U-04 | 8 份不同結果，故意讓一份 INVALID | 8 列精簡清單、長度受控、錯誤不掩蓋同批合法檔案、零 Preview 寫入 |
| U-05 | Preview 後確認匯入 3 份可新增檔案 | 只有核准檔案寫入；版本區更新；Preview 消失或保留時仍有 24px 間距 |
| U-06 | 建立至少 21 筆合成版本紀錄 | 日期升／降冪、10／20／50 每頁、下一頁、篩選跨頁結果正確；同日多版本顯示無歧義 |
| U-07 | 同日不同內容並手動確認替換、回復 | 既有 Active Batch、版本回復與防衝突行為不回歸 |
| U-08 | 1280／1366／1440 CSS px | 無水平溢出，檔名／按鈕可操作，主要區塊 `getBoundingClientRect()` 間距量測符合 |

驗收證據至少包含：

- 1280、1366、1440px 的桌面截圖；其中 **1366px** 至少要有未 Preview、五檔 Preview、Confirm 後三種狀態。
- 實際測得各可見主要區塊間距（單位 CSS px），例如 `Selection.bottom → Preview.top`、`Preview.bottom → History.top`、無 Preview 時 `Selection.bottom → History.top`。
- 表格排序／分頁互動錄測或 Browser E2E 證據（不只畫面截圖）。
- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 通過；既有匯入、品質規則、版本回復相關測試不得退步。
- 未執行的瀏覽器情境要明列「未驗證」，不可直接宣稱已通過。

## 7. 安全、範圍與交付

- 僅修 Excel 匯入頁與為排序／分頁所需的最小查詢整合；不重寫 Parser、ETL、SQLite 品質規則、統計公式。
- 不修改歷史加工／異常事件圖表 UI、組員尚未定版的篩選與視覺規格。
- 不修改企業 Excel／JSON，不呼叫企業 API。
- 不刪除或重建既有正式 SQLite、Import Batch、Docker Volume；不得以清 DB 的方式讓 UI 測試通過。
- 不 Push、不部署、不開始 Stage 6/7；不執行破壞性 Git 指令。
- 使用現有 `dev` 分支；保護未提交改動，通過測試的完成切片可做本機 Commit。
- 更新 `docs/BUILD_LOG.md`，新增 `docs/STAGE5_2_EXCEL_UI_FINAL_ACCEPTANCE.md`，記錄設計變更、修改檔案、測試證據、已知限制、Commit Hash、工作樹狀態。

**驗收定義：不再以「已寫 gap CSS」、「已有折疊警告」、「版本清單有搜尋」等代替實際畫面與互動驗證。完成本文件所有已授權事項後停止。**
