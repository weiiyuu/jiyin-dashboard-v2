# Stage 5.2 補充執行規格｜Excel 匯入頁 UI、批次預覽及效能驗收

> 用途：與 `docs/STAGE5_2_EXCEL_DATA_QUALITY_EXECUTION_SPEC.md` 一併執行，**只補充 Excel 匯入頁面與效能的驗收標準**。不得擴張到歷史分析／異常分析圖表、首頁或 Stage 6–7。
>
> 使用者於 2026-11-14 人工檢查目前 Excel 匯入頁，確認下列缺陷仍存在。這是 UI 驗收缺口，不表示 Stage 5.1 已通過的程式測試無效。若本補充文件與原 Stage 5.2 文件在 Excel UI 的具體布局上衝突，以本文件的明確要求為準；資料安全、驗證、統計資格、版本與交易規則仍以原文件為準。

## 1. 修正目標與範圍

- 解除「上方區塊／Preview／匯入版本紀錄」在不同狀態下緊貼、沒有間距的問題。
- 解決選擇大量檔案時，右側「匯入規則」卡片被左側文件列表連帶拉長、產生大片無意義空白。
- 保留**每份檔案獨立預覽決策**，但從大型雙欄預覽卡重設為「批次摘要＋精簡逐檔清單＋展開詳情」，避免 8 份檔案造成頁面過長。
- 使多檔 Preview 的成本、處理狀態及上限清楚可見；用實測評估效能，不宣稱任意數量都能一次處理。
- 與 Stage 5.2 `ACCEPT`／`ACCEPT_WITH_WARNINGS`／`INVALID`／`REVIEW_REQUIRED` 等資料品質決策對接；不擅自變更後端原則。

## 2. UI-01｜所有主要區塊統一間距（高優先）

**可重現情境 A**：開啟 `/imports`，未選任何檔案、未執行 Preview；「選取與預覽＋匯入規則」之下的「匯入版本紀錄」直接相接，缺少留白。

**可重現情境 B**：選取一份或 8 份檔案、點擊「預覽並驗證」；Preview 結果卡直接接在上方兩卡之下，但 Preview 和「匯入版本紀錄」之間又有不同間距。

**驗收**：頁面主要 Section 由單一父層 `display:flex; flex-direction:column; gap:24px` 或等效 Grid Gap 管理。至少包含：

1. 上方兩欄「選取與預覽＋匯入規則」；
2. 條件顯示的「Preview 結果」；
3. 「匯入版本紀錄」。

沒有 Preview 時，上方兩欄和版本紀錄仍有 24px 間距；有 Preview 時，兩處相鄰 Section 間都為 24px。避免 `margin-top` 僅在某個條件分支才生效、`gap:0`、負 margin 或邊框疊接。內部小元件的間距可另定，不必全為 24px。

## 3. UI-02｜左／右卡片不互相拉高（高優先）

**可重現**：一次選 8 份約 500KB 的標準化 XLSX，左側檔案列表已限制高度並可內部滾動，但右側「匯入規則」卡依然被撐成與左側一樣高，留下一大片空白。

**要求**：

- 上方兩欄在桌面版保留左右比例（可等寬），**頂部對齊、不強制同高**。檢查實際 CSS 的 grid/flex `align-items:stretch`、`height:100%`、`min-height`、`grid-auto-rows` 等，最小差異調成自然高度；例如 grid `align-items:start`，對右卡 `align-self:start; height:auto`，以現有實際程式碼為準。
- 左側選檔區隨少量檔案自然成長；超過 4–5 份時，檔案列表限制高度約 260–320px，在列表內捲動，不連帶拉長右卡。選取數／總大小、移除／清除全部與 Preview 按鈕仍可到達且易操作。
- 右側規則卡內容保留必要資訊，但可簡化技術術語；不為了湊高度塞入假 KPI 或裝飾文字。
- 窄版在合理 breakpoint 改成單欄，不在 1280px 起強制水平捲動。

## 4. UI-03｜Preview 改成摘要與可展開逐檔列表（高優先）

**為什麼逐檔結果不能刪**：各檔有不同來源日期、資料量、品質、重複／衝突判斷、確認動作與 `ACTIVE_VERSION_CHANGED`，必須讓使用者知道哪些可以安全寫入、哪些會略過或需要手動確認。**逐檔結果必要，但大型逐檔卡片不是必要。**

**建議預設版面**：

- Preview 頂部顯示：所選檔案數、可新增數、完全重複數、需處理的警告／錯誤／衝突數、可 Confirm 數。計數必須從 API Response 導出，不得硬編碼，若分類重疊須讓標示口徑一致。
- 預設用單欄精簡列表或表格，每行只顯示：日期／短檔名、決策狀態、機台/環境/Alarm 筆數（可次要顯示）、錯誤/警告數，以及「查看詳情」；8 檔完整列表不應強迫使用者穿越 8 張大型卡片。
- 結果列表限制最大高度（建議約 400–480px），超出在內部捲動；也可分頁，但不可預設整批大型卡全部展開。捲動容器要清楚可操作，並避免巢狀捲動困難。
- 每列展開後才顯示各警告類別中文名稱、說明、筆數、影響（入庫或統計）、行號範例；詳細清單也應限制高度或分頁，避免數千筆警告撐爆頁面。`DERIVED_VALUE_MISMATCH` 等工程代碼僅作技術補充。
- 狀態文案（繁中）：`可新增`、`可新增但含品質警告`、`完全重複，略過`、`同日不同版本，需確認替換`、`驗證失敗，不能匯入`、`需審閱`；以實際 Stage 5.2 Contract 為準。空來源／來源缺失不可混為一談。
- Confirm 按鈕附近用清楚摘要說明「本次將新增 X 份、略過 Y 份、替換 Z 份（需要確認）、其餘不能匯入」；**不可因整批某檔 INVALID 就誤允許它 Confirm**，也不能把重複檔再次寫入。替換、回復、CAS、Preview 零寫入和每檔 transaction 沿用原安全契約。
- 錯誤或警告不能只靠色彩辨識；至少有中文標題與具體描述。對尚未展開的 `INVALID`，必須直接可見「驗證失敗」與錯誤數，不能被摘要掩蓋。

**精簡與細節平衡**：使用者可以快速看完整批狀況，但要能追查某份檔案的原始行號和原因。

## 5. UI-04｜資料品質摘要應與 Stage 5.2 的 NULL 政策一致

- `rule_name=NULL` 或其他核准的可空描述欄不再顯示「阻擋性錯誤」；顯示「來源未提供、已保留缺值、可匯入」，並記錄相應 issue；不得自行補成官方規則名稱。
- 重要觀測 NULL 或嚴重不足秒數的來源仍可保存，但 Preview 要顯示「資料已收到 vs 可用於哪些統計」的差別，並且有明確受影響行數。
- 6/4 00:54 多台秒數不足屬資料品質通知，不能用 Red/Yellow 設備故障語意呈現。僅在本地 UI 顯示批次摘要／詳情，不實作即時通知或外部訊息。
- 原始上傳檔、SQLite Active/REPLACED、duplicate/conflict、rollback、NULL≠0、quality eligibility 必須維持正確。

## 6. UI-05｜多檔預覽效能與回饋（中高優先）

**現行限制維持**：最多 8 檔／請求；單檔壓縮 25 MiB；整批 50 MiB；其他展開後大小與 cell 數安全檢查照原 Stage 5.2 規格。

**必須做**：

- 用 1、2、4、8 份**合成標準化 XLSX** 測試 `POST /api/imports/preview` 的端到端耗時、最大記憶體（可量測則記錄）、HTTP Status、有效／無效／混合結果及 Preview 零資料庫寫入；在 `STAGE5_2_ACCEPTANCE.md` 列出**實測數據、硬體／模式及限制**。不要以截圖或主觀猜測報一個固定秒數。
- 預覽進行時顯示明確 loading，防止重複提交，失敗可以重新嘗試；超限在 client 和 server 都有一致訊息；不要將 8 檔全都載入後才忽然告知超限。
- 若現有 Preview 是單一同步請求，前端**只能顯示整批處理中與已完成結果**，不可造假每檔即時進度百分比。真要逐檔進度必須建立有根據的 API/任務追蹤，不在本次最小必要範圍內。
- 不因急著提高速度而取消 OOXML/ZIP、公式、外部連結、指紋、交易和版本保護；避免毫無上限的平行讀取導致資源飆升。依量測結果再判斷是否需要有界並行、分批 Preview 或日後非同步佇列。
- 五個月大量資料的「資料夾選取／背景排程／自動批次佇列」列作後續擴充候選，**本 Stage 不自動加做**。

## 7. Browser / API 驗收案例（完整重現條件）

1. **無檔案、無 Preview**：`/imports`，本機已有 6/1 與 6/2 Active Batch；上方兩卡與「匯入版本紀錄」間有約 24px 空隙。右卡自然高度。
2. **1 份檔案**：選 `2025-06-03` 的合成可匯入檔，檢查選檔清單自然高度、預覽按鈕能用；Preview 後上方與 Preview、Preview 與版本紀錄都有約 24px 間隙。
3. **8 份檔案**：選八份約 0.5MB／份的合成標準化 XLSX；左側檔案列表最多約 260–320px 高、可獨立捲動；右側規則卡不被拉長；Preview 逐檔緊湊清單且在約 400–480px 高度內捲動。
4. **混合狀態**：選已有相同 fingerprint 的 6/1、6/2，加上有 `rule_name=NULL` 的 6/3、有嚴重不完整區間的 6/4、正常 6/7 及故意缺表頭的檔案；結果要清楚區別 `DUPLICATE`、`ACCEPT_WITH_WARNINGS`、`ACCEPT`、`INVALID`；錯誤不可混成 500，無效檔不得 Confirm。
5. **大量警告**：一個檔有 70 筆 `DERIVED_VALUE_MISMATCH`；預設只顯示類型＋數量＋少量例子，展開才能看行號詳情；頁面沒有長到不可操作。
6. **不同顯示尺寸**：桌面/筆電 `1280×720`、`1366×768`、`1440×900`，至少檢查正常狀態、8 檔清單與 Preview 展開態。不能產生水平頁面溢出、按鈕消失或可點區塊被覆蓋。
7. **退化及安全**：無法讀取、超過 8 檔、超過容量的錯誤須可辨識；預覽不寫入、Confirm 後批次版本及品質摘要正確，重新載入頁面仍能讀取舊版資料。
8. **原始私人附件**：若 Codex 未取得真實 6/1–6/5 Excel，應用合成同型 fixture；不得宣稱測過原檔，並保留人工實測待辦。
