## 1. 目標與非目標

**目標**：使用者能依日期及類型，快速得知「有多少來源警示、平均／最長多久、哪天集中、哪些來源最多」，並能從事件明細追溯來源；同時能獨立分析機台**紅燈出現的累積時間與區間**，不將燈號直接視作已確認故障。

**非目標**：故障原因診斷、設備故障率/OEE/良率/產量推估、即時企業 API 警報中心、通知推播、事件人工結案、修改原始 Excel、修改 Collector、重新設計 SQLite 主資料結構。黃燈代表狀態時間，不列入「正式異常事件數」，保留在機台運轉分析頁。

## 2. 來源資料與關鍵業務定義（必守）

### 2.1 三類來源，兩個 V2 分析主軸

| 資料類別 | 主要來源 | V2 用途 | 統計單位／限制 |
|---|---|---|---|
| **來源環境警示** | Active Batch 的 `alarm_events` | 警示次數、持續時間、趨勢、感測器排行、明細 | 每一筆符合「環境/類比感測器警示」分類的來源列計 1 筆**警示紀錄**；不稱唯一故障事件或設備故障次數 |
| **機台紅燈** | Active Batch 的 `machine_3min.Red秒` | 紅燈累積時間、連續出現區間、機台排行及明細 | 依品質合格 Red 秒數加總；出現區間群組≠故障事件 |
| **機台黃燈** | Active Batch 的 `machine_3min.Yellow秒` | 只保留原功能／追溯，不納入 V2 異常 KPI | 黃燈不自動等於故障或異常；原始欄位不可刪除 |

`alarm_events` 也可能有 `加工完成通知`（例：`lamp`、`A3列印完成`）。此類來源列**不得混入「環境警示次數」**；必須根據既有來源分類／型別及可辨識欄位作正向分類，不可僅靠字串包含「Alarm」全部計入；未知分類要標示待確認，不能默默視為環境異常；在來源資訊提示中明示「另有 N 筆未分類／非異常通知未納入」，讓使用者知道統計篩選邊界。

**依使用者核對單日標準化檔所得的決策**：來源 Alarm 列數可以用來計數，但前提是先區分環境警示與非異常通知。原始資料確實含可解析的英文持續時間；不得將原始 Excel 或私人內容納入 Git，實作／自動測試用合成測試資料。

### 2.2 警示持續時間

- 來源為 `alarm_events.持續時間原文`，可能如 `2 hours 51 minutes 20 seconds`、`12 hours 14 seconds`、`35 minutes 59 seconds`，也可能是 NULL 或未知格式。
- **保留來源原文字串**。另建立純計算用 parse：支援英文字單複數、不同單位組合與空白差異；只允許明確、非負、可完整解析的時分秒，勿推測未提供的單位或秒數；不符合者 `durationSeconds=null` 並給予可追溯的解析狀態。
- 平均 = `sum(valid durationSeconds) / count(valid durationSeconds)`；最長 = `max(valid durationSeconds)`。**分母只計有有效持續時間的警示**；「來源警示總數」仍計全部符合分類的紀錄。
- 顯示採「X 小時 Y 分 Z 秒」，一般卡片取整秒即可；計算保留原始秒數，避免先四捨五入再求平均。可在備註標示「依 N 筆有持續時間資料計算」。
- 有持續時間 ≠ 來源確認已結束；**不可**用是否有 duration 推導「已結束／未結束」、事件關閉時間、事件是否仍正在發生。
- 如果警示在查詢期間內開始，來源記錄的持續時間可能延伸超出結束日；不擅自裁切為日期範圍內時長。清楚說明「依事件發生時間篩選，持續時間使用來源原值」。

### 2.3 事件數、版本與來源可用性

- 只讀取**目前啟用的 Active Batch**；不因同日多個匯入版本而重複計數。
- `alarm_events` 沒有可證明全域唯一的企業事件 ID，**不可**宣稱「正式唯一事件數」，也不可跨來源版本靜默合併不同內容。
- 事件日期依來源**事件開始時間**及 `Asia/Taipei` 歸屬；單日依 00:00–23:59 小時桶，多日依日期桶。每日數量以該期間內開始的合格來源警示列計算，跨日持續時間不重複算到次日。
- `PROVIDED_NONEMPTY`＝有提供且有紀錄；`PROVIDED_EMPTY`＝有提供但明確 0 筆；`MISSING`／`UNKNOWN`＝來源不足以判讀，**不可畫 0**。沒有 Active Batch 的日期亦為缺資料。
- 若選取期間中只有部分日期的 Alarm 來源可判讀，KPI 與圖表可呈現**已知部分**，但必須附「來源已提供 X/Y 天，結果不代表全部日期」；全部缺資料時以 `—` 與原因提示呈現，不顯示 0。
- `quality_issues` 與來源分類狀態若表示需確認，要在明細保留註記；不能把尚待確認的分類當成已證實故障。

### 2.4 紅燈連續區間群組

- 同一機台，兩筆三分鐘資料的**絕對時間恰好相鄰**、兩筆 `Red秒>0` 且各自通過 Red 指標資格，才可合併成同一出現區間群組。遇 `Red=0`、缺列、不合格即斷開；跨來源日須兩天都有效且時間連續。
- 群組保留 `firstStart`、`lastEnd`、`rowCount`、`sumRedSeconds`、跨來源日標記與相關資料品質狀態。
- **顯示務必區分**「發生時間範圍 10:00–10:09」與「累積紅燈 4 分 20 秒」。三筆相鄰不代表完整 9 分鐘都亮紅燈，也不是三次故障。
- 僅在有效資料下統計。缺資料不補零；已確認有效且 Red=0 才是 0 秒。

## 3. 整體頁面資訊架構（固定五區）

依序：**分析範圍 → 三張統計卡 → 異常發生趨勢 → 異常事件明細 → 異常來源排行**。不再將舊版大段連續紅黃燈清單和每日來源覆蓋卡放在主視覺；必要追溯內容移至明細展開區／精簡提示。

### 3.1 分析範圍（對照 `01_filter.png`）

**第一層僅三項**：開始日期、結束日期、異常類型，排列沿用現有卡片和欄位組件。日期含首尾，最多 366 天（若現有後端限制更嚴，先核對並一致顯示）。預設選擇最近有 Active Batch 的合理短日期範圍（建議 7 天）；不要以今天無歷史資料導致空白畫面。

異常類型選項：
- `全部類型`（預設）：同頁可看來源環境警示與機台紅燈，但**不同量綱不相加**。
- `來源環境警示`：專注 Alarm 紀錄數與持續時間。
- `機台紅燈`：專注紅燈累積時間和區間。

**進階篩選**預設收合：區域 A/B（可確認區域 mapping 才用）、機台 A1–B4（僅紅燈有意義）、感測器 ID／名稱、規則名稱（僅來源警示有意義）。`全部類型` 下個別來源的篩選不能意外排除另一來源；應採明確的分組／切換或說明。未知區域不要從感測器名稱猜測。

操作區在所有條件**最底部右側**，只提供「重設條件」與「套用篩選」；條件變更不自動送出以免多次查詢。成功套用後 KPI、趨勢、表格、排行都依同一次已套用條件更新；條件改動尚未套用時提示。

### 3.2 三張統計卡（對照 `02_kpis.png`）

**朋友版三張卡是本頁核心樣式**。在 `全部類型` 與 `來源環境警示` 模式，三卡如下：

1. **環境警示紀錄數**：符合分類的 Alarm 來源列數，單位「筆」。小字：`有持續時間 N 筆／未提供 M 筆`；來源缺漏另有明確提示。不要寫「正式唯一事件」。
2. **平均警示持續時間**：有效來源 duration 的平均；小字：`依 N 筆有持續時間資料計算`。
3. **最長單筆警示持續時間**：有效來源 duration 的最大值；小字同上。

`全部類型` 模式另以精簡的次要文字顯示「機台紅燈累積 X 小時」，或在後續圖表切換中讀取，不把紅燈群組數混進 Alarm 總數；**不額外增加一排大型 KPI**。

在 `機台紅燈` 模式，保持三卡外觀但改成：① 紅燈累積時間（`sumRedSeconds`）；② 紅燈出現區間群組數；③ 出現紅燈的機台數。不可將群組數命名成故障次數。

若沒有資料：**有資料且確定為 0**才顯示 `0`；缺來源／無有效分母顯示 `—` 和原因；平均／最長在零筆有持續時間的情況下顯示「無法計算」。

### 3.3 異常事件發生趨勢（對照 `03_trend.png`）

沿用現有「機台運轉分析」的折線圖、Tooltip、圖例、按鈕與配色語言；單日依小時、多日依日。不要複製朋友圖的獨立視覺樣式。

- 警示模式：Y 軸 `來源環境警示紀錄數（筆）`，由**來源事件開始時間**計數，單日 24 個小時桶／多日依各日期。
- 紅燈模式：Y 軸 `累積紅燈時間（小時或分）`，以有效 `Red秒` 加總；**不可**將三分鐘紀錄數或連續群組數混充事件數。時間桶需按與現有歷史分析相容的聚合規則分配，跨桶使用原始三分鐘區間的正確歸屬。
- `全部類型`：圖表右上方提供既有樣式的 segmented control：`警示筆數`／`紅燈時數`；預設警示筆數。切換不重置日期與區域；Y 軸單位隨之更新。單一圖表不把兩種單位畫到同一 Y 軸。
- 真正 0 筆／0 秒可顯示 0；`MISSING/UNKNOWN`／無有效資料以空點、中斷線段與 Tooltip 說明，不補 0。必要時沿用朋友的缺資料 `×` 提示，但符合現行圖表語言。
- 圖下方採**單行精簡來源覆蓋摘要**：`警示來源已提供 X／Y 天`（或紅燈可統計資料 X/Y），不再顯示大量按日卡片。
- Tooltip 依模式顯示日期／時段、數值、單位、來源可用性、缺漏提醒；不使用「正式故障數」。

### 3.4 異常事件明細（對照 `04_details.png`）

保留朋友的六欄表格感覺與每頁 20 筆、**最新在前**；使用者可展開查看完整來源資訊。建議欄位：

| 欄位 | 來源 Alarm 模式 | 機台紅燈模式 |
|---|---|---|
| 發生時間 | 原始事件開始時間 | 區間 firstStart |
| 來源 | 感測器顯示名（輔助 Sensor ID） | 機台 A1–B4 |
| 分類 | 來源環境警示 | 機台紅燈出現區間 |
| 規則／狀態 | 原始規則名稱，無值顯示「規則名稱未提供」 | 紅燈出現 |
| 持續時間 | `持續時間原文` 可解析則顯示中文、無值顯示未提供 | **累積 Red 時間**（非完整區間跨度） |
| 資料備註 | `來源已提供／未提供持續時間／待確認` | `可統計／品質提醒` |

- `全部類型`：明細上方用 `來源 Alarm`／`機台紅燈` 小型分段切換，避免不相容的欄位塞在同一列表；預設 Alarm。切換仍套用日期條件。
- Alarm 展開：事件時間、感測器 ID／名稱、群組、類型、規則名稱、規則條件、當前值與原文、持續時間原文、初步分類與分類狀態、來源日期與 Active Batch 追溯。沒有來源獨立結束狀態時**不可**顯示「已結束／未結束」。
- Red 展開：機台、完整時間起迄、涵蓋三分鐘筆數、累積 Red 秒數、是否跨來源日與品質備註。簡潔的時間區段視覺可以放在展開內容，不再另開主頁大區塊。
- 分頁與排序：時間 DESC，再以穩定唯一 row key 打破同時刻平手；重查／改條件頁碼歸 1；後端分頁，保留每頁 20 筆，必要時沿用現有可重用的頁碼／跳轉控制。不一次把全部明細載入前端。
- 窄螢幕表格內部捲動或選擇性收斂欄位；避免整頁水平溢出。技術詳細資料保留在展開內容，不強迫主表長文換行。

### 3.5 異常來源排行（對照 `05_ranking.png`）

沿用既有歷史圖表的全寬水平 Bar、末端數字、滑過 Tooltip 與排序視覺；以數值降序。

- Alarm 模式：依**感測器 ID**分組，顯示友善感測器名稱；Y 軸來源，X 軸警示紀錄筆數。
- Red 模式：依 A1–B4 機台分組，顯示累積紅燈時間（非紅燈事件次數）。
- `全部類型`：圖表右上切換 `警示筆數`／`紅燈時數`（可以與趨勢圖的指標切換共用同一狀態，但不要使使用者困惑）。
- 數值和 KPI 使用**相同篩選與資料版本**；在無額外分組排除時，來源排行所有項的 Alarm 筆數合計應等於已知來源警示紀錄數。
- 預設 Top 8；來源較少則全部顯示。大於 8 可看完整排行，但避免把 30+ 列一次撐開首頁。
- Tooltip 補充完整感測器名稱、ID、區域（僅有可靠 mapping 時）、警示筆數／紅燈時數及資料可用性；未知分類不得自動加入正式異常排行。

## 4. 介面一致性與無障礙

- 使用現有 Burgundy Dark UI 的 card、spacing、border、字級、按鈕、Tooltip 與 loading/empty/error pattern；不要平行造第二套 Chart CSS。
- 首屏三張統計卡排成 3 欄，窄螢幕可 2 欄／1 欄；卡片同排高度穩定，主數值不得破版。
- 中文文案短而清楚：`警示紀錄`、`可統計資料`、`未提供`、`來源缺漏`；資料定義與技術碼放 Tooltip／展開詳情。禁止用 `已確認故障`、`未結束事件` 等來源不支持的詞。
- 圖表／表格正常處理 0、null、部分日期無來源、超長感測器名稱、長規則與多筆結果；Tooltip 不出畫面；手機尺寸不出現頁面級水平溢位。
- 查詢最多 366 天的性能要受控：統計在後端聚合，明細分頁，不將 366 天所有明細與整批三分鐘原始列傳回瀏覽器。

## 5. 技術落地與測試界線

**先調查現有資料來源與 API，最小變更實作：**

- 頁面既有位置：`src/app/history/events/page.tsx`。
- 現有唯讀 API：`GET /api/history/events`。若回應已具相應欄位則重用；不足部分可為 KPI／趨勢／排行新增最小的唯讀聚合欄位／輔助端點，不動 Excel 主資料及 Collector。
- 使用現有 `Active Batch`、來源完整性、品質排除與版本 CAS 原則。若既有 Alarm parser/分類邏輯不足，新增可測的純函式；**不改寫原始 `持續時間原文`**。
- 不用全域 `Alarm count` 與 `Red seconds` 相加；不同單位有獨立格式與分母。
- 視覺參考圖從 `_reference_inputs` 唯讀使用；不要把 5 張參考圖或大量 UAT PNG 放進 Git。
